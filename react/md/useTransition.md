# useTransition

`useTransition` е начинът да кажеш на React "това обновление не е спешно". Обновленията вътре в `startTransition` попадат в TransitionLane: рендерират се на порции, могат да бъдат прекъснати от всичко по-важно и не замразяват екрана. Hook-ът дава и `isPending`, за да покажеш на потребителя, че нещо догонва. Тази страница показва с истински React какво се променя за потребителя и какво не.

## Аналогия: сервитьор с два вида поръчки

Сервитьор получава едновременно "чаша вода" и "пица за осем човека". Ако носи поръчките в реда на пристигане, водата чака пицата. Умният сервитьор носи водата веднага, а пицата, когато е готова. `startTransition` е начинът да кажеш на React коя поръчка е пицата. Водата (буквата в полето) се появява веднага; пицата (филтрираният списък) идва след секунда, а през това време на масата стои табелка "приготвя се" (`isPending`).

## Демо: пиши и мери

<div data-widget="use-transition"></div>

Две числа са важни. "От клавиша до буквата" е колко време полето е било замръзнало. Без transition то е равно на пълния рендер на списъка, с transition е няколко милисекунди. "От клавиша до актуален списък" е почти еднакво и в двата режима, понякога малко по-дълго с transition: React не прави работата по-бърза, а я мести на по-късно и я реже на порции.

## API

```jsx
import { useState, useTransition } from 'react';

function Search({ items }) {
  const [query, setQuery] = useState('');
  const [filter, setFilter] = useState('');
  const [isPending, startTransition] = useTransition();

  function onChange(e) {
    const value = e.target.value;
    setQuery(value);                              // спешно: полето трябва да покаже буквата веднага
    startTransition(() => {
      setFilter(value);                           // не е спешно: списъкът може да догони
    });
  }

  return (
    <>
      <input value={query} onChange={onChange} />
      <ul style={{ opacity: isPending ? 0.5 : 1 }}>
        {items.filter((i) => i.includes(filter)).map((i) => <li key={i}>{i}</li>)}
      </ul>
    </>
  );
}
```

Има и самостоятелна функция `startTransition` от пакета `react`, без `isPending`, за код извън компоненти (например в store). Hook-ът е за компоненти, където искаш и индикатор.

## Какво прави и какво не прави

| Прави | Не прави |
|---|---|
| Слага `setState` извикванията в TransitionLane (нисък приоритет) | Не прави рендера по-бърз: същата работа, същото общо време |
| Позволява рендерът да се реже на порции по 5 ms ([Time Slicing](Time_Slicing.md)) | Не пуска нищо в друг thread |
| Позволява рендерът да бъде прекъснат и започнат отначало при по-спешно обновление | Не отменя стария transition "по магия": новият го заменя, резултатът е последното състояние |
| Дава `isPending`, докато transition рендерът не е commit-нат | Не отлага самия `setState`: стойността се сменя веднага, само рендерът чака |
| При Suspense показва старото UI вместо fallback, докато новото се зареди | Не работи с legacy `ReactDOM.render` |

## Кога да го ползваш

- Филтриране, сортиране, смяна на изглед над голям списък или таблица.
- Навигация между "страници" в едно приложение, когато новата страница е тежка за рендер или чака данни през Suspense.
- Смяна на таб, която рендерира много компоненти.

## Кога да не го ползваш

- За стойността на контролирано поле. Ако `setQuery` е в transition, буквата ще се появи със закъснение, точно обратното на целта. Спешното обновление остава спешно.
- За едно единствено бавно изчисление. Transition реже между компонентите, не вътре в тях. Виж ограниченията на [Time Slicing](Time_Slicing.md).
- За обновления, които потребителят чака като пряк отговор на действието си (отваряне на модал, toggle). Там закъснението дразни.
- Ако ти трябва да отложиш стойност, която не контролираш (идва от props или от библиотека), използвай [useDeferredValue](useDeferredValue.md).

## Suspense и transition

Ако компонент вътре в transition рендера спре заради Suspense (чака данни), React не показва fallback-а, а продължава да показва старото UI с `isPending === true`. Без transition същото обновление би заменило готовото съдържание със спинер. Това е поведението, което прави навигацията между страници плавна: старата страница остава, докато новата е готова.

```jsx
function onNavigate(page) {
  startTransition(() => setPage(page));   // старата страница остава видима, докато новата се зареди
}
```

## Капани

- Преди React 19 функцията в `startTransition` трябва да е синхронна: `setState` след `await` вътре в нея вече не е част от transition-а. В React 19 async transitions са поддържани, но пак е добре `setState` да е веднага след `await`.
- `isPending` става `true` веднага и `false` едва след commit. Ако transition-ът бъде прекъснат и рестартиран няколко пъти, остава `true` през цялото време.
- Transition обновления на едно и също състояние се сливат. Не очаквай междинни стойности да стигнат до екрана.
- `console.log` в render на тежкия компонент ще показва повторения при прекъсване. Това е нормално.
- Transition не е debounce. Ако потребителят пише бързо, React пак започва рендер след всяка буква, само че го изхвърля при следващата. За мрежови заявки все още ти трябва debounce.
